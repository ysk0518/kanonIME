# 背景変更の診断ログ

設定画面または背景編集画面の下部で「デバッグログ」をオンにすると、下にコンソールが表示されます。既定はオフです。設定の保存操作とは独立した即時切り替えです。

## 再現の手順

1. デバッグログをオンにして、必要なら「消去」を押します。
2. 背景画像を選び、設定画面のプレビューを確認します。
3. 「保存」を押します。
4. 確認用の入力欄などでkanonを表示します。
5. 設定画面へ戻り、コンソールのテキストを長押ししてコピーします。

あわせて端末名、OSバージョン、kanonの版、静止画かGIFか、保存後の表示メッセージを伝えてください。画像そのものを共有する必要はありません。

## 記録内容

- `settings`: 画像選択・保存操作、IMEの受信確認
- `image`: 読み込み段階、寸法、変換後のデータ量、エラーコード
- `gif`: 選択時の容量・フレーム数、加工設定・結果
- `background`: 保存、分割転送、受信・適用、ACKとタイムアウト
- `preview`: 一時プレビュー画像の転送・復元
- `render`: 画像の描画用デコードの成功・失敗
- `console`: ログ用通信の接続・失敗

行頭はUTC時刻と処理元（`app` / `ime`）です。IMEプロセスからのログは同じアプリ内に限定した共通イベントで集約します。システム全体のログを取得する機能ではありません。

最新160件だけをメモリに保持し、ファイルには保存しません。15分で自動オフになります。入力文字、候補本文、画像データ、画像URIやファイルパス、例外のメッセージは記録しません。画像を表示したログはデコード完了を示すもので、画面全体の見た目が正しいことまでは保証しません。

## プレビューは出るのにIMEに反映されない場合

| ログ | 切り分け |
|---|---|
| `settings save pressed` がない | 保存操作まで進んでいない可能性 |
| `disk save failed` | 設定保存に失敗。エラーコードを確認 |
| `publish failed` / `transfer failed` | 共通イベントの発行・転送に失敗 |
| `transfer sent` はあるがIME側の `receive complete` がない | IME未起動、購読失敗、分割データの欠落などを確認 |
| `ack timeout` | 保存済みだが、IMEからの受信確認が時間内に届いていない。原因を単独では断定できない |
| `receive applied` / 対応版の `ack` がある | 設定の受信・保存まで完了。描画や一時プレビューの復元を確認 |
| `render decode failed` | 描画側で画像を読み込めていない |

オンにした直後にも現在の設定の版・画像データ量を記録して同期を要求します。ログ用の共通イベント自体が届かない場合はIMEの行も届かないため、必要に応じてHDCのログと照合します。
