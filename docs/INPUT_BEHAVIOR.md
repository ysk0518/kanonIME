# 入力動作の仕様

更新: 2026-11-25。入力操作の基準は Gboard（Android、日本語・英語）。

入力中・候補選択中・確定後の期待結果を定める。[実装仕様](KANON_SPEC.md)の入力操作を具体化する文書。

## 1. 読み方と対象

| 記載 | 扱い |
| --- | --- |
| 合意 | 会話で選び、採用してきた製品要件。変更には仕様と受入条件の更新が必要 |
| 継続 | 現在の実装を継続する条件。今回新たに他IMEとの一致を確認したものではない |
| 提案 | 採用を決める前の案。テストの期待値や製品動作をこれに合わせて変更しない |

日本語・英語、12キー・QWERTYが対象。配列が違っても、同じ文字・操作が届いた後の確定規則は揃える。
数字・記号の配列表示と、入力エンジンの言語・未確定状態は別に扱う。記号画面の表示だけで確定を要求しない。
候補内容・順位・文節の自動分割は辞書に依存する。他IMEとの完全一致や全入力欄での動作保証はしない。

例の`今日[は？]`は「今日が確定済み、は？が未確定」。`[か│き]`の`│`は未確定内の挿入位置。
これは説明用の記法で、入力欄への括弧の表示を要求するものではない。

## 2. 状態

| 状態 | 意味 |
| --- | --- |
| 未確定なし | 既存の本文はあってよい。IMEが編集中の文字はない |
| 入力中 | 読み・英字・記号を編集中。予測候補が表示されても候補選択中とは限らない |
| 候補選択中 | Space／変換で候補を強調したが、まだ確定していない |
| 範囲調整後 | 日本語の候補選択中に左右操作で対象文節の区切りを変更した |
| 部分確定後 | 前方の文字は確定済み、後続は入力中または候補選択中。後続の状態を引き継ぐ |
| 英語の補完直後 | 補完を確定済みで、元の接頭辞へ戻せる条件を保持している |

「候補選択中」は候補をタップして確定した後を含めない。
未確定の有無は文字の下線や候補数から推測せず、エンジンとIMEの状態で扱う。

## 3. 共通の条件

- 1回の操作で同じ文字を二重入力・二重確定しない。入力先の更新が遅くても同じ書き込みを再送しない。
- 未確定を確定したEnterでは、同時に検索・送信・改行を要求しない。未確定なしのEnterは入力欄のアクションへ渡す。
- 予測候補を表示しただけでは確定しない。未選択の候補をEnterや言語切替で勝手に採用しない。
- 文字・記号の追加だけで、既存の未確定文字や対象範囲外の後続を消さない。
- 部分確定は「確定した部分」と「残った未確定」を分ける。残りへ続けて入力・削除・濁点変更を行える。
- かなに変わった文字のDeleteでは、元のローマ字入力へ巻き戻さない。
- 入力先が変わったら、古い入力要求・候補・応答・補完Undoを新しい欄へ持ち込まない。
- 未確定表示の成功、カーソル配置の成功、確定の成功を区別する。取得失敗を空欄やカーソル位置0として成功扱いしない。

| JP-17 | 範囲調整後 | 候補タップ／Enter | 先頭から対象文節までを確定する。対象より後ろの文字は確定・破棄せず、残りの候補を更新する | 合意 |
| JP-18 | 部分確定後 | 文字・Delete・濁点入力 | 残った未確定を同じ編集状態で扱う。消した文字を再生したり、確定した接頭部分を変更しない | 合意 |
| JP-19 | 入力中・候補選択中 | 候補一覧の「取消」／ツールバーの「再開」 | 「取消」は候補選択中ならJP-20と同じく読みに戻し、入力中なら未確定を保持する。どちらも一覧を閉じる。「再開」は復旧用で、未確定を消し確定済み本文を保持する | 合意 |

### 確定範囲の例

- 入力中`[きょうは？]`でEnter：`きょうは？`を全体確定する。
- Spaceで変換後、対象が「きょう」のときEnter：`今日[は？]`。残りまで同時確定しない。
- 範囲を「きょう」へ縮めて候補「今日」をタップ：`今日[は？]`。
- 途中挿入`[か│き] → さ`：`[かさ│き]`。そこで部分予測「傘」を確定する場合は`傘[き]`。

文節と候補は例として指定する。辞書がその候補・区切りを返すことは、操作規則とは別に確認する。

補完Undoは現在の入力先・カーソル・単語と一致する場合だけ使う。
自動Undoが無効なら通常Deleteへ進む。明示的な「戻す」は通常Deleteへ置き換えない。
Undoの編集が失敗した場合、同じ操作で別の削除や再送を追加しない。

## 6. 英語：未確定表示に非対応の入力欄

直接入力では、`he`はすでに入力欄に入っている。候補選択の表示を本文への未確定表示と混同しない。

| ID | 操作 | 期待結果／現状 | 扱い |
| --- | --- | --- | --- |
| DE-01 | 英字入力 | 入力欄へ直接挿入し、許可された欄では接頭辞の補完候補を更新する | 継続 |
| DE-02 | Space、候補あり | 候補を強調・巡回する。入力欄の接頭辞はそのままで、空白を追加しない | 合意 |
| DE-03 | Enter、候補選択中 | 足りない末尾だけを1回追加する。`he → hello`で`hellohello`や`hehello`にしない | 合意 |
| DE-04 | Enter、接頭辞あり・候補未選択 | 入力済みの文字を保持して予測状態だけを終了する。このEnterで送信しない | 合意 |
| DE-05 | 候補タップ | 接頭辞・候補revision・カーソルを照合し、該当候補の末尾だけ追加する | 継続 |
| DE-06 | 補完直後のDelete | 有効なUndoなら追加された末尾を削除し、元の接頭辞の予測を復元する。本文を再挿入しない | 継続 |
| DE-07 | 補完確定前のDelete | 候補選択中は強調だけを解除し、入力欄の接頭辞を保持する。強調がなければ通常の削除を行う（CM-06） | 合意 |

候補なしのSpaceは半角空白を追加する。予測状態のないEnterは入力欄のアクション。
パスワード種別では予測・補完・未確定表示を使用せず、直接入力する。欄の属性に従った制約は別途実機確認する。

## 7. 切り替え・貼り付け・入力先

| ID | 操作 | 期待結果 | 扱い |
| --- | --- | --- | --- |
| CM-01 | 日本語／英語の切り替え | 表示中の未確定を全体確定してから言語を切り替える。未選択の予測は採用しない | 合意 |
| CM-02 | 12キー／QWERTYの切り替え | 未確定を全体確定してから配列を変え、言語を保持する。文字を失わない | 合意 |
| CM-03 | 未確定中の貼り付け | 全体確定の成功を待ち、貼り付け文字列をそのまま追加する。確定失敗・入力先変更では貼り付けしない | 継続 |
| CM-04 | アプリ内／アプリ間の入力先変更 | 古い未確定・候補・遅い応答を新しい欄へ転送しない。OSが旧欄をどう確定するかは別の観測 | 整合性の条件 |
| CM-05 | 操作中のAPI失敗 | 成否不明の書き込みを再送しない。成功表示・二重入力・別操作での破壊的な代替を行わない | 整合性の条件 |
| CM-06 | 本文／英語未確定のDelete | 確定済み本文は選択範囲またはカーソル直前の1書記素、英語未確定は末尾の1書記素を削除する。絵文字の連結・修飾・国旗・キーキャップ、異体字セレクタ、タグ列、結合文字をまとめて扱う。本文はHarmonyOSのdeleteForwardが文字（書記素）単位で数えるため、常にdeleteForward(1)を送る（実機D25で確認）。直前が空なら何もしない。英語未確定はIMEが書記素の長さを計算する。日本語未確定はMozcで処理する | 合意 |
| CM-07 | Spaceドラッグの感度 | ドラッグ18vp、タップ許容12vp、1イベント16移動を採用する。今後の数値変更は感度の調整として扱う | 合意 |

キーボードを閉じることと、入力先・OSの未確定セッションが終了することは同義としない。
外部タップ・選択通知だけで文字の確定・消失を推測しない。

| ID | 扱い | 決定 |
| --- | --- | --- |
| Q1 | 合意 | 日本語の変換中Deleteで残りの未確定全体を読みに戻す。Mozcの既定キー割り当てに従う（JP-20） |
| Q2 | 合意 | 直接英語の候補選択中Deleteで強調だけを解除する（DE-07） |
